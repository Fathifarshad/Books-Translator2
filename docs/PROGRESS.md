## Phase 2 — Backend, database, PDF ingestion, structure review
- [x] All synthetic fixtures match golden JSON — `fixtures/pdf/{outline-book,two-column,no-outline}.pdf` (generated by
  `pnpm fixtures:pdf` from original text) vs `*.expected.json`, checked by `packages/pdf/src/golden.test.ts`
  (`UPDATE_GOLDEN=1` rewrites them; every golden was reviewed by hand). Covers outline → TOC, printed Contents page →
  TOC, headings fallback, page labels (i, ii, 1…), running heads/page numbers removed, dehyphenation (compounds kept),
  paragraph/list-item continuation across pages and columns, two-column order, footnotes, code, captions,
  front/back matter and default skips.
- [~] Real text-based PDFs: TOC = outline; no running heads/page numbers in text; < 1% suspected mid-sentence breaks —
  the rules are in place and reported per book (`suspectedBreakRatio` in the report, `pnpm pdf:inspect --html`), but
  no real book is in the repo (SPEC §16); the owner still has to run it on their own PDFs.
- [x] 300+ page PDF ingests without blocking the API, with live progress — `apps/api/src/large-book.test.ts`:
  320 pages in ~4 s in a worker thread, `/health` stays < 500 ms during ingestion, SSE progress reaches 320/320.

### Phase 2 — what exists (summary)
- `packages/pdf`: pdf.js 6 (legacy build) extraction in a worker thread → lines → header/footer cleanup → columns →
  blocks → continuation merge → structure (outline / Contents page / headings) → report. `pnpm pdf:inspect <file.pdf>
  [--pages 10-20] [--html out.html] [--json out.json]` prints blocks and structure; the HTML overlay shows every page
  with coloured block boxes.
- `apps/api`: SQLite (WAL) + Drizzle migrations, FTS5 search (source + translation, Persian-normalized), uploads in
  `data/uploads/<bookId>/` (SHA-256 duplicate check, 200 MB / 2000 pages limits), DB-backed job queue with leases
  (resumes after a crash), SSE per book (progress/job/book events, heartbeat), structure edits (rename, skip, promote,
  demote, merge, split, confirm) that never change segment ids, `DELETE /books/:id`.
- `apps/web`: library from the API (status per book, delete), add-book step 1 (drag & drop, upload progress, duplicate
  → «open the existing book»), step 2 (live extraction progress, report with warnings), step 3 (structure editor with
  preview and split picker), reader reading the API bundle (source-only rows until translated), server search.
